# agents 与 Dev Companion 的适配评审

## 结论

原仓库是一套只读代码分析团队，适合为已有项目提供结构、依赖、构建与风险的现状输入。它没有开发执行、用户需求或功能验收协议，因此不能直接充当新手软件开发团队。保留该用途，新增 Dev Companion 的主会话流程与开发者、独立检查者角色；不要求简单任务启动所有分析角色。

## 已修正的分析团问题

| 问题 | 修正 |
|---|---|
| 私人 Windows 绝对路径 | 显式 team_root 与宿主安装路径 |
| 工作流 camelCase、角色制品 snake_case 不一致 | 统一契约及运行时字段检查 |
| 分块截取 24、验证截取 20，但设计要求完整覆盖 | 去掉静默截断，检查逐文件覆盖及全部待验证结论 |
| 提示词中的闸门缺乏代码判断 | G1–G5 检查字段、证据、重复、遗漏和引用 |
| refuted 与未验证结果混淆 | 区分 verified、refuted、unverified；未闭合标明 partial/blocked |
| 黑板复用与目标污染风险 | 显式目标外输出，独立 run_id，宿主预检真实路径与排他创建 |
| 强制写入 Toh 记忆 | 移除未经用户要求的记忆写入 |

分析团的闸门检查结构，不证明代理声称的文件读取一定真实；真实路径预检和制品落盘依赖宿主工具。动态工作流的测试使用 mock 宿主，真实 DWF 运行是单独验证层。

## Dev Companion 的实际首版

包含需求卡、范围版本、任务包、实现回报、实际命令检查、必要的用户确认、派生完成度、Markdown/静态 HTML 面板、跨会话状态与显式文件快照。

状态规则：已实现不直接计入验收；检查失败、未执行或内容变化都不能报完成；整体目标或单项验收条件变化需要重新验收；重复或迟到回报不能覆盖新状态。文件权限变化也使检查过期。范围变化保留历史。

存档规则：不碰用户 Git；普通文件显式纳管，拒绝链接/路径逃逸/常见凭据路径。恢复 token 绑定预览时的内容，恢复前生成可核对的保护存档。部分恢复失败保留故障标记并暂停后续制作、检查和写入，不能自动当作成功。

## 设计取舍

- 使用 Python 3.9+ 标准库，避免新手先安装服务或第三方依赖。
- 显式命令与共享技能为首版入口，暂不加入 Hook/MCP 自动化；界面为可信信息卡和静态 HTML。
- 第一个版本每次派发一项功能，减少多写入者造成的变更归属歧义；已有分析工作流仍可并行读取。
- 普通项目文件指纹用于保守识别变化，整个项目变化可能要求再次检查原功能；没有伪装成精确依赖分析。
- 验收必须有约定自动检查；用户交互是否符合要求仍需要检查者和实际用户判断。CLI 是记录与检查工具，不是安全沙箱，也无法证明检查覆盖完整。
- 本地快照是新的明确范围实现，不使用原派发单中语义不正确的 `git revert <目标>`。它不是全盘、异地、数据库或线上服务备份。

## 验证层次

1. Python 回归验证真实项目记录、命令检查、文件内容与双向恢复。
2. Node 24 测试执行分析工作流并模拟宿主，验证结构闸门和调度。
3. ZCode 随包校验器验证插件清单；实际安装后分别检查命令与技能发现。
4. 模型执行和新手试用需要独立结果；前三级通过不自动代表第四级通过。

各命令、记录目录、示例和安装方法见插件 README。公共分发时只包含源码与演示，不包含用户项目状态、真实日志或本地路径。

## 本次实测记录（2026-09-20）

- Python 3.9.6：36 项状态与快照回归通过；示例的 4 项测试通过。
- Node 24.19.0：36 项工作流测试通过，其中包含 27 块和 31 条结论不截断的用例。
- ZCode 桌面 3.14.0 / 内置 CLI 0.16.9：两插件 manifest 与市场清单校验通过，安装并启用；六个 companion-* 入口、swarm-analyze 和 dev-companion 技能被实际发现，诊断为空。
- 安装时发现旧用户 my-team 命令优先遮蔽以及内置 resume 冲突，已通过插件命名前缀解决，保留原用户命令。
- 在隔离演示项目中真实走完需求、检查、验收、两次存档、恢复、撤回与重新检查，并生成静态看板。此结果是自动化演示，不是真实新手试用。
- ZCode 桌面独立验证任务实际加载安装副本的技能与接口，并执行 doctor、status markdown/json，均退出 0，读出 revision 8、1/1 已验收、证据未过期，同时识别“非真实用户试用”。该验证覆盖到进度查询，没有派发开发者。
- 独立 CLI 的模型请求另有宿主问题：默认找不到 bundled provider 配置；使用源码支持的单进程配置路径变量后仍报 Model creation failed。没有修改用户模型或凭据设置；桌面调用路径已通过上述只读验证。
- 真实 ZCode DWF、大规模项目、桌面完整开发/检查派发链和新手可用性试用仍未验证，不由以上结果代替。
