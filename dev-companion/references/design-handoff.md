# 设计交接契约

本文件是 companion-design 角色与下游（companion-developer 实现、companion-checker 核对）共同引用的契约：设计 brief 按下面的最小结构编写和交接。示例仅演示结构，所有内容必须替换为真实界面的事实；示例文字不证明设计已被联审或冻结。本契约由 packages/agents_kernel/contracts/schemas.py 的校验器守护（机器校验为准）。

## 设计 brief 的最小结构

| 字段 | 含义 | 填写规则 |
|---|---|---|
| brief_id | 设计版本标识 | 一份 brief 一个 id；内容修订即换新版本，冻结后的 brief 不再原地修改 |
| feature_id | 对应功能编号 | screen_id 与 feature_id 一一挂钩，不写无主页面 |
| brief_version | 版本号 | 递增整数；与冻结内容一一对应 |
| based_on | 复用的现有界面与栈 | 写真实文件路径或生成入口；声明复用什么、排除什么 |
| screens | 页面清单 | 每屏一条：用户操作顺序、状态矩阵、组件与状态映射、响应式、可达性、设计验收标准 |
| non_goals | 非目标 | 显式列出容易混淆的相邻设计，防止范围蔓延 |

## 状态矩阵：五态缺一不可

每个界面逐一枚举五态，写明数据形态与界面文案：

| 状态 | 含义 | 填写规则 |
|---|---|---|
| loading | 数据未就绪 | 写真实来源：静态产物登记"打开即快照"，异步界面写加载中的数据形态与文案；不虚构不存在的加载过程 |
| empty | 无数据 | 写空数据形态（空数组、null）与引导文案 |
| error | 读取或恢复失败 | 写失败来源与提示原文 |
| partial | 部分可用 | 写部分受阻或证据过期时的降级展示 |
| success | 正常 | 写正常数据形态与主文案 |

适用时补充 stale（数据过期）、unauthorized（未授权）等额外状态；某态在当前界面确实不存在时，写明该事实与理由，不留空也不删。

## 组件与状态映射

组件优先映射既有样式语汇（如原生单文件看板的摘要卡、自适应网格、状态徽章、折叠说明、深浅色变量），新组件给出与既有语汇一致的最小说明；每个组件写清复用来源与在哪些状态下出现。

## 响应式与可达性最低标准

桌面与窄屏各给一句布局结论；可达性至少覆盖：界面语言属性、状态不单独靠颜色传达、交互元素可键盘操作（原生元素优先）、正文对比度。设计验收标准必须可操作、可断言：每条写明具体操作与预期结果，使用"出现/不出现/等于/包含/不低于"等可核验措辞，不写"界面友好"之类无法断言的话。

## 与角色的关系

companion-design 按本结构产出设计 brief 并自检五态与断言措辞；companion-developer 按冻结后的 brief 实现，静态模拟稿不算实现完成；companion-checker 按每条设计验收标准逐条核对。需求歧义或范围变化回流 companion-product 与用户；交互不可用或验收不可断言回流 companion-design 修订，并递增 brief_version。
