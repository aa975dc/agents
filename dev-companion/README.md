# Dev Companion · 新手开发陪伴

把一句想法整理成可确认的需求，交给开发者实现，让你看懂实际进展、体验成果，并保存需要保护的本地文件。

这是 ZCode 插件 `dev-companion`，版本 `0.1.2`。它包含六个命令、一项共享技能、开发者与独立检查者，以及使用 Python 3.9+ 标准库的本地工具。没有必装 MCP、Hook 或云服务。

## 适配你现有的智能团

你的 `code-analysis-swarm` 适合了解已有项目：它做只读体检、收集证据、交叉验证和形成报告。它的职责不包含修改代码或产品验收。

Dev Companion 保留这一分析能力，通过两个小角色补齐执行：

```text
新手的想法 → 需求卡与验收例子 → 确认首版
                              ↓
                 必要的现状分析（可用原分析团）
                              ↓
                开发者制作 → 独立检查 → 用户试用
                              ↓
                  可信进度 → 文件快照 → 继续工作
```

小改动按需做定向阅读；陌生大型项目再使用完整分析团。分析团是同仓库的可选独立插件，Dev Companion 不要求每个功能启动所有分析角色。

## 在 ZCode 安装与开始

1. 准备本仓库的本地副本，确认仓库根目录有 `marketplace.json`。市场目录是仓库根，不能选成 `dev-companion/` 子目录。
2. 打开 ZCode 的“插件市场 → 添加（有的界面显示创建）→ 添加插件市场”，选择或粘贴该本地仓库根目录。
3. 在“个人”分组找到该市场，安装 `dev-companion` `0.1.2`。需要全面只读分析时可再安装同市场的 `code-analysis-swarm`。
4. 在目标项目中新建任务，在输入框的 `/` 菜单选择插件的 `companion-start` 命令，或从技能菜单选择 `dev-companion`。以菜单实际名称为准。
5. 输入：“我想做一个给自己用的记账工具，先帮我说清楚最小版本要做什么。”

你应该先看到需求卡和少量问题。确认本次需求后才开始制作；不需要自己编写 JSON 或给智能体分工。先试用现成样例请看 [演示步骤](examples/README.md)。

源码、市场清单和安装副本是不同位置。本地文件齐全不代表已经安装，也不代表 ZCode 内的实际体验已经验证。已有安装更新时：刷新原市场 → 在插件详情更新 → 新建任务验证；修改源码不会自动更新安装副本。插件开关在“设置 → 插件”管理。

## 常用入口

在 `/` 菜单中选择对应命令，再输入你的说明；也可用自然语言表达同样的意图。

从 `0.1.1` 起，入口统一使用 `companion-` 前缀，避免与 ZCode 内置命令或用户已有命令重名。下表是聊天入口名称，技术文档中的 CLI 子命令名称保持不变。

| 入口 | 你可以说 | 插件做什么 |
|---|---|---|
| `companion-start` | “我想做一个……” | 整理需求卡、验收例子和首版范围 |
| `companion-progress` | “现在做得怎么样？” | 展示真实状态、阻塞和下一步 |
| `companion-work` | “继续做下一项” | 派发开发者并安排独立检查 |
| `companion-check` | “检查这个功能；我试过后发现……” | 检查当前成果，记录有效的试用反馈 |
| `companion-archive` | “保存这些文件”或“先预览恢复” | 保存、查看快照，预览并确认恢复 |
| `companion-resume` | “接着上次继续” | 恢复项目目标、当前进度与未决事项 |

用户临时增加功能时，先说明新增内容和影响，再更新范围。已经明确授权的常规执行会持续推进，不需要每一步重复确认。

## 看懂完成度

进度按“已验收功能 / 当前范围全部功能”计算，每项等权。受阻仍属于未完成工作。需求未确认或数据无法读取时，不显示虚构的百分比。

| 发生了什么 | 应怎样理解 |
|---|---|
| 开发者报告实现 | 产物已提交，仍待检查 |
| 检查通过 | 约定的自动检查成功，还需核对覆盖及必要的用户试用 |
| 已验收 | 当前内容满足本次验收要求 |
| 已保存快照 | 显式纳管的文件已保存在本机 |
| 100% | 当前范围全部验收，不等于已上线 |

示例卡片是展示方式，下面的数字是虚构示例：

> 个人记账工具 · 首版
>
> 已验收 2/5；待检查 1；制作中 1；受阻 1
>
> 下一步：体验本月合计，录入 20 元与 30 元，确认显示 50 元。
>
> 待你决定：记录只保存在本机，还是需要跨设备？

真实面板由 CLI 从项目台账生成，不能由 AI 随意填写。可以生成静态 HTML 概览；它需要重新生成才会刷新，没有后台实时监控或可点击执行按钮。

## 文件保护范围

状态放在项目 `.dev-companion/`，插件升级不覆盖这份项目数据。快照仅包含显式选择并纳管的普通文件；本地快照不是 Git 仓库镜像、异地备份、数据库备份或线上服务恢复。

恢复前先停止所有写入，展示具体增改删清单，得到用户对该预览的确认后执行。恢复会先验证操作前保护快照。目标快照中没有的较晚纳管文件可能被删除，预览会列出；从未纳管的文件不受恢复影响。撤回恢复也通过保护快照重新预览与确认。

敏感文件、符号链接和目录会被拒绝。规则无法识别源码里所有潜在秘密，保存前仍需确认选中文件的内容合适。保存失败、内容变动、任务仍在运行或令牌过期时不能宣称恢复成功。

## 架构与实现边界

| 模块 | 位置 | 职责 |
|---|---|---|
| 新手流程 | `skills/dev-companion/` | 需求引导、授权判断、白话解释 |
| 明确入口 | `commands/` | 开始、进度、开发、检查、存档、续接 |
| 执行分工 | `agents/` | 限定范围开发、独立核验 |
| 状态工具 | `scripts/companion.py` | 台账、任务包、回报、检查与完成度 |
| 文件快照 | `scripts/archives.py` | 保存、恢复预览、保护与恢复 |
| 接口材料 | `references/`、`examples/` | 数据格式、宿主适配、可运行示例 |

重要的当前限制：

- 需要 ZCode 的文件读取、进程执行和 Agent 能力。没有某项工具时明确报告该步骤未执行，不能绕过宿主权限。
- 首版要求可执行自动检查；人工口头认可不能代替技术检查。适合先从小型本地工具开始。
- 变更指纹覆盖有上限：普通文件单个不超过 20 MiB、累计不超过 100 MiB、最多 10000 个文件。排除的敏感配置、数据库和外部服务变化无法自动识别，需要主动告知并重新检查。
- 执行范围和验收条件由提示词与工具共同维护；检查脚本仍是项目代码，CLI 不是隔离沙箱，也无法代替人工判断检查覆盖质量。
- 项目内记录能识别登记中的运行任务，但无法自动停止其它编辑器或外部进程；恢复前必须实际停止所有写入者。
- 不包含自动部署、外部同步、原生侧边栏和跨项目调度。显示本次实际验证覆盖，不能据此许诺任意项目都能无人值守完成。

技术接口见 [CLI 约定](references/cli-contract.md)，宿主加载和分析团协作见 [ZCode 接入](references/zcode-integration.md)。

## 验证与后续实施

开发环境可从仓库根运行 `python3 -m unittest discover -s tests -v`，检查状态与快照的重要行为；示例独立测试见 [演示说明](examples/README.md)。自动测试与 manifest 校验通过后，仍需在实际 ZCode 中验证安装、角色派发和完整用户流程。

后续按结果推进：先完成目标 ZCode 的实际体验，再用 5 位新手检查能否说清需求、看懂进度和完成试用；据此调整提问与展示。只有确实需要时再接入自动刷新、更多项目类型或远端备份。
